# 보스방 확장 · 부서지는 발판 · 보스방 문 · 혈류 구덩이 수정 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 메인씬 보스방을 1.5배로 넓히고, 부서지는 발판 2개와 보스전용 입구/출구 문을 넣고, x≈30 혈류 구덩이를 고친다.

**Architecture:** 게임 동작은 새 런타임 스크립트 3개(`BossRoomDoor`, `BreakablePlatform`, `BossRoomController`)로 만든다. 씬 수정은 에디터 메뉴 한 개(`Tools/메인씬/보스방·혈류 수정 적용`)가 Unity API로 메인씬을 직접 고친다. CompositeCollider2D가 자식 블록을 합치고 있어서 씬 YAML을 직접 고치지 않는다. 사용자가 메뉴를 한 번 누르고 저장하면, 씬 파일을 파서(스크래치패드 `tools/scene.cs`)로 읽어 수치를 검증한다.

**Tech Stack:** Unity 6000.0.72f1, C#, 2D Physics, Undo API

**Spec:** `docs/superpowers/specs/map-changes-preview.html` + 대화에서 정한 결정 (아래 Global Constraints)

## Review Focus

1. 부활 직후 플레이어가 입장 감지 영역 밖(체크포인트 2, x≈206)에 있으므로 입구 문이 열린 상태여야 함 — 보스 처치 전 재도전 가능.
2. 보스가 발판 위에 착지했다가 발판이 부서지면 정상적으로 떨어져야 함 (발판 콜라이더 끄기만, 오브젝트 파괴 안 함).
3. 복구 시점에 플레이어가 발판 자리에 서 있으면 끼이지 않아야 함 — OverlapBox로 확인 후 대기.
4. 보스를 이미 잡은 뒤 죽으면 문이 다시 생기지 않아야 함.
5. 메뉴를 두 번 눌러도 블록이 두 번 잘리거나 문이 두 개 생기지 않아야 함 (이미 적용됐으면 중단).

테스트 방식: 이 프로젝트는 테스트 어셈블리가 없고 Unity가 열려 있어 배치모드 실행이 불가하다. 각 태스크 검증 = (1) `dotnet build Assembly-CSharp-Editor.csproj` 0 오류, (2) 메뉴 실행 후 씬 파일 파서로 수치 확인, (3) 사용자 플레이 확인 체크리스트.
